# p2pfs

软件工程实践小组项目：P2P 存储文件下载工具。

通过服务端发现分片来源，客户端优先直连多个节点下载，打洞失败时由服务端中转，并在取得足够有效分片后利用 Reed–Solomon 纠删码恢复文件。

## 当前阶段

当前处于需求明确阶段。需求文档 0.2 已记录项目发起人的范围确认，细化设计和小组评审仍待完成，尚未代表功能已经实现或测试已经通过。

## 已确定的范围与技术约束

- 服务端：Linux，Go + Echo v5 + SQLite
- 客户端：首发仅 Windows，Go + Wails 3；具体系统版本与 CPU 架构待定
- 文件数据传输：UDP，STUN 辅助打洞；优先直连，失败后通过服务端 UDP 中转
- 服务端职责：维护设备在线状态和文件 chunk 分布，同时承担中转数据面；不要求永久存储文件内容
- 身份：第一版不做账号系统；客户端连接服务端后由服务端分配 UUID 作为标识。UUID 不是秘密凭据，重连是否沿用待设计确认
- 实验基线：k=4、m=2，首期单文件最大 1 GiB；接受需求文档第 7、8 节实验目标
- 文档：以 GitHub 仓库 Markdown 为共同来源；实际课程日期与提交格式细节仍需补齐

STUN 不保证所有网络都能直连；服务端中转也不能保证覆盖 UDP 全面阻断的网络，当前未加入 TCP 文件传输回退。中转不能替代离线来源或补出缺失分片。
